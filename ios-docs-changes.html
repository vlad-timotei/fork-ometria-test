Where the docs diverge from your README

Below is every place the published Docusaurus iOS docs read differently from the README you sent. Each item is either an SDK-source mismatch, a syntax/runtime issue, an Apple-spec correction, or a small content addition. Nothing else differs.

SDK source contradicts the README

NSE override method name

SDK source
README
override func initializeOmetria -> Ometria? {
    Ometria.initializeForExtension(...)
}
Docs
override func instantiateOmetria() -> Ometria? {
    return Ometria.initializeForExtension(...)
}
Source: Sources/Ometria/OmetriaNotificationServiceExtension.swift declares open func instantiateOmetria() -> Ometria?. The README's initializeOmetria doesn't exist in the SDK.

Source: OmetriaNotificationProcessor.swift docstring: "Call this method from your NotificationService.didReceive function." The signature takes UNNotificationRequest + contentHandler — both only available inside an NSE's didReceive. The benefit is avoiding the subclass, not the NSE target.

OmetriaBasket.totalPrice (not price)

SDK source

The README's property list in §6 says price; the README's own code example uses totalPrice:. Docs use totalPrice.

SDK source

handleNotificationResponse example must call completionHandler()

SDK source

The README example in the swizzling-disabled section omits completionHandler() after handleNotificationResponse(response). The SDK passes withCompletionHandler: nil internally and never invokes the developer's handler — so without an explicit call, the system never gets told the response was handled.

Source: Ometria.swift → handleNotificationResponse(_:) body: notificationHandler.handleNotificationResponse(..., withCompletionHandler: nil).

Basket-item example — missing comma

Syntax

The README example has variantId: "variant-product-1" followed directly by sku: on the next line, with no comma between them. Won't compile. Docs add the comma.

Universal-link handler — missing return values

Syntax

The README's application(_:continue:restorationHandler:) example never returns a Bool. Docs add return true / return false.

Apple spec corrections

apple-app-site-association uses hyphens

Apple spec

The README says apple_app_site_association (underscores). Apple requires the file be named with hyphens; if uploaded with underscores, iOS won't recognise it. Docs use the hyphenated form.

Content the docs add (extension, not contradiction)

SPM-based setup for the Notification Service Extension target

Addition

The README's NSE section only shows the Podfile route for adding Ometria to the NSE target. Since the README also adds SPM as a top-level install option, the docs add a parallel SPM step for the NSE target: select the NSE target → General → Frameworks and Libraries → add Ometria.

Without this, SPM integrators have no documented path for wiring the NSE.

Everything else in the docs matches the README. If any of the SDK-source items above are actually intended (renamed methods, new APIs landing), let me know and I'll re-verify against a specific branch.
